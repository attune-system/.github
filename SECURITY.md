# Security policy

## Reporting a vulnerability

Report suspected vulnerabilities privately through
[Attune's private vulnerability reporting form](https://github.com/attune-system/attune/security/advisories/new).
This channel accepts reports about any repository in the `attune-system`
organization. Include the affected repository, version or commit, impact, and
steps to reproduce. Use test credentials and redact secrets and personal data.

Do not disclose an unfixed vulnerability in a public issue, pull request, or
community chat. If the affected public repository offers its own **Security →
Advisories → Report a vulnerability** button, that is also an appropriate private
channel.

## Supported versions

Attune is pre-production. Security fixes normally target current development and
the latest applicable release. Older releases do not have a guaranteed security
backport or support window. Related SDKs, deployment files, and packaging follow
their own published compatibility requirements; include their versions in reports.

## Response and disclosure

One maintainer currently handles reports. We aim to acknowledge reports within
7 calendar days and provide a triage update within 14 calendar days, but these
are best-effort targets, not a guaranteed response time.

We coordinate disclosure with the reporter after assessing impact and preparing
a fix or mitigation. There is no fixed disclosure deadline for every report;
please discuss timing privately, especially when other projects are affected.
We publish advisories when appropriate and credit reporters with their consent.
